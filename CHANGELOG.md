# Changelog

This file follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and DoubleAgent's versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The first release of `doubleagent`, one program with the commands `collect`, `detect`, `timeline`, `fleet` and `catalog`. If you used the earlier collector scripts and Python analyzer, [Differences from the scripts](docs/differences-from-the-scripts.md) lists what changed.
- `collect` gathers Atlarix, flagging with `secret: true` its sign-in session files, `user-settings.json`, `core-session.key` and, on Windows, `Local State`, with the temporary copies an interrupted save leaves beside them: its data directory (`Library/Application Support/Atlarix`, `AppData/Roaming/Atlarix` or `.config/Atlarix`) without its `shadow-snapshots` and `cache` folders and the desktop app's Chromium caches (`Cache`, `Code Cache`, `Crashpad`, `DawnGraphiteCache`, `DawnWebGPUCache`, `GPUCache`, `blob_storage`), `~/.atlarix` without `bin` and the relay program `chrome/atlarix-bridge-*.exe` the Windows CLI copies there, the developer-mode data folder `~/.atlarix/dev-data` without its `cache` and `shadow-snapshots` folders, with its session files, `user-settings.json` and `core-session.key` flagged `secret: true`, and a project's `.atlarix/` and `.atlarixignore`. A startup file that sets `ATLARIX_USER_DATA_DIR`, `ATLARIX_HOME_DIR`, `ATLARIX_SKILLS_DIR`, `ATLARIX_CLI_STATE_FILE`, `ATLARIX_HEADLESS_OUTPUT_FILE` or `ATLARIX_HEADLESS_TRAJECTORY_FILE` gives a relocation hint. `detect` lists the files as `atlarix`, which no parser reads yet ([#60]).

### Changed

- On Linux and macOS a candidate home that cannot be looked at for a reason other than not existing, such as a passwd home below a directory the account cannot enter, is now logged `profile not accessible (skipped): PATH` and, when its parent directory lists it, gets an `error_read` row, as on Windows, where it was dropped with no line and no row. Its user now counts as found, so a `-u` naming it no longer warns that it matches no user home ([#631]).
- The analysis commands read an agent's TOML files as TOML 1.1, which adds to TOML 1.0 a newline or a trailing comma inside an inline table, a time or date-time without seconds, and the `\x` and `\e` string escapes: a file using one of these now gives its rows where it gave one error row. Every TOML 1.0 file reads as before ([#569]).
- `collect` keeps its staging directory open for the whole run and stages, archives and removes through it, so moving the directory aside and putting a link at its name during the run no longer sends staged copies through the link; on Windows the directory cannot be renamed or deleted while the run works, and on a volume that keeps access lists (NTFS) it is made with its own, the running account and Administrators only, while on FAT, exFAT or a network share it is made as any other directory there. A run now ends with exit `2` (`Cannot create staging dir: ...`) when the staging directory it has just made and opened is not an empty directory it can take as its own, and leaves that directory in the output directory ([#542]).
- When several Docker volume patterns match one volume name, the most specific one now decides which agent the volume is collected as: the pattern with the fewest `*`, then the one with the most literal characters, then the one whose agent, and then pattern, sorts first, where the first pattern listed won before. A new `*ollama_data` pattern keeps a Local Deep Research compose project's `local-deep-research_ollama_data` volume with `ollama`. A volume name that holds the names of two agents can now go to the other agent, for example `ollama_n8n_data` to `n8n` rather than `ollama` ([#583]).
- Results and output order no longer depend on the order of lines in the catalog: they follow agent and then pattern. Each table is read into that order (the relocation variables by agent, variable and replaced path, the exclusion and credential patterns by pattern, and the startup files by scope and pattern), and the catalog file is sorted the same way, each comment heading one agent's lines. Everything that followed the file's order changes order with it: the manifest rows and the log's match lines of each home in a `collect` run, the agent and `evidence` lines of `collect --inventory`, the order relocation hints are found and logged in, the agents of `catalog --agents` (now alphabetical), and the rows of the table and the file list `detect` prints: for a loose tree directly, and for a collection through the order of its manifest rows. Of two Docker volume patterns of different agents that are equally specific, the one of the agent whose name sorts first now wins, so a volume name holding both `tabby` and `letta` goes to `letta`, and one holding both `ollama` and `hermes` to `hermes` ([#583]).
- The manifest `agent` of the `symlink` row of a symlinked directory that catalog paths run through now names who reached through the link: the agent whose paths matched through it, or `shared` when paths of more than one agent did, where it named one of those agents alone. A home whose `~/.config` links to a directory holding `amp/` and `goose/` now has that row under `shared`, and one holding only `amp/` under `amp`. A link that leads out of the image root, behind which nothing is listed, has its log line and its row under `shared` (`[shared] <link>: the symlinked directory leads out of the image root; ...`), whichever agent's catalog lines reach it. A link that the walk of a catalog match records is recorded as before, under that match's agent ([#593]).
- Within one walk, `collect` writes each manifest row as it reaches the path, and visits a directory's entries in the order the directory lists them, on every platform. Linux and macOS wrote a walk's rows in groups by status, and Windows visited a directory's subdirectories before its files, which also put a wildcard catalog line's matches there in that order; each `copy failed:` line now follows its file's match line in the log everywhere. This item changes the order of the rows, not their content ([#606]).
- A `collected` row's `size` is the number of bytes copied, which `sha256` covers, on every platform; on Linux and macOS it was the size from before the copy, which differs for a file that grew while it was copied. An excluded directory's `skipped_excluded` row on Linux and macOS now carries the directory's own times, owner and group numbers and mode, where they were `0` (its `size` is the sum of the sizes of the files below it, [#619] says how). `collect --inventory` on Linux and macOS now prints `read failed: DIR: REASON` for a directory it cannot read, as on Windows ([#607]).
- Exclusion and credential patterns written for the root of a Docker or Podman volume (such as `library`, `bin`, `models`, `config`, `settings.json` and `ssh/*`) are now tried only below a volume's `_data` directory, never under a home or a project. The catalog format changes: such a line in `# excluded unless --full` or `# credential files (flagged secret, skipped with --no-secrets)` starts with `volume|`, and `collect --list` and `catalog` print it that way. A home directory such as `~/bin` or `~/tools` is now searched for relocation hints under `--env-scan-home`, where these patterns kept it out of the search ([#586]).
- Every pattern in every catalog table now ignores ASCII letter case on every platform, and a matched path is spelled as the directory holding it lists it. On Linux and macOS a catalog line spelled in another case than the disk now matches it, so a Windows image mounted case-sensitively matches the lines written for it; a directory holding two names that differ only in case (`Goose` and `goose`) has both matched by one line, each collected under its own spelling and flagged or pruned by the same exclusion and credential patterns; and those patterns ignore case in every directory, not only where the directory does. Each line's matches are sorted bytewise on every platform, where Windows kept the directory's order. The catalog lists each path once: the lines `.config/Goose` (goose), `.config/pearai/User` (pearai), `Crush.md`, `crush.md`, `Crush.local.md` and `crush.local.md` (crush) and the exclusion `.config/Atlarix/Cache` are removed, and `[Zz]ed`, `[Cc]rew[Aa][Ii]`, `[Gg]oose` and `[Aa]ntigravity` become one spelling, which `collect --list`, `catalog` and the `collect --inventory` `evidence` field show. On Linux the Cursor CLI's `.config/cursor` and the Devin CLI's `.config/devin` lines now also take the Cursor and Devin editors' `~/.config/Cursor` and `~/.config/Devin` whole, where only their `User`, `logs` and (for Cursor) `update-supervisor` directories were collected: new exclusions there leave out the editors' caches (`Cache`, `CachedData`, `CachedExtensionVSIXs`, `CachedProfilesData`, `Code Cache`, `Crashpad`, `GPUCache`) and Cursor's process logs (`process-monitor`), and new credential patterns flag their `Cookies` with `secret: true`. On a case-sensitive Linux disk `.config/goose` now also collects the Goose desktop app's `.config/Goose` whole, as on a Mac. A pattern holding a character class name, a backslash or an unclosed bracket, which the catalog never holds, now matches nothing. Below a directory that can be entered but not listed, which gives no listing to compare with, a line finds only the name it spells, or on a disk that ignores case the name in any case, recorded as the first line to reach it spells it. So on a disk that keeps case, below a `~/.config` that cannot be listed, pearai's `~/.config/pearai/User` on Linux and the Goose desktop app's `~/.config/Goose` are no longer collected, since no line now spells them that way ([#611]).
- The log no longer has a `find: DIR: REASON` line for a directory that cannot be listed; its `read failed:` line and `error_read` row say the same. A directory whose listing fails after it was found readable now also gets an `error_read` row and a `read failed:` line, where it had only the `find:` line; the entries read before the failure are still collected, as before ([#608]).
- On Linux and macOS the `size` of an excluded directory's `skipped_excluded` row and of an unmatched volume's `skipped_unmatched_volume` row is now the sum of the sizes of the files under it, as on Windows, where it was the space allocated as `du -sk` reports it, in whole KiB: a directory of small files now has a smaller size, and one on a compressed or sparse file system can have a larger one. A file with several hard links is counted under each of its names, and a symbolic link under the directory counts nothing, where its own blocks were counted ([#619]).
- On Linux and macOS the `mode` of a row for a path whose metadata cannot be read is now `""`, as on Windows, where it was `"0"`; a `"0"` now always means a file whose permission bits are all off ([#620]).
- On Linux and macOS whether a directory can be read is decided by opening it and reading one entry, and whether it can be entered by looking up a name in it, as on Windows (which has no entry check, since every account may pass through a directory), where a permission check (`test -r` and `test -x`) decided first. The entry is read only from a directory that can be entered, so a directory that cannot is never listed and keeps its access time. A directory the permission check refused although the system let the run open and list it is now collected, where it had an `error_read` row reading `permission denied`; an `error_read` row's `error` is always the error of the step that failed ([#621]).
- The archive no longer holds the directories above a file that was not copied (excluded, too large, a secret under `--no-secrets`, a special file): a directory is made in the staging directory only to stage a file or link in it, so the archive holds an empty directory only where the copy of a file into it failed or a link could not be recreated in it. The manifest does not change ([#622]).
- A `copy failed:` log line no longer ends `; staged path resolves outside the staging directory, not removed` for a file whose staged path leads through a recreated link out of the staging directory: its reason already ends `does not resolve inside the staging directory`, and nothing was opened or written ([#623]).
- On Windows `collect` never sets a source file's access time. When the access time changes while the run asks Windows to hold it, the `access time not held:` line says `access time changed while the hold was asked for` and the time is left as it is, where a change to a value no real access could write (the request itself, a date before 1980 or one more than 50 years ahead) was set back and logged as `hold not honoured, access time restored` or `hold not honoured, restore failed`; those two reasons are gone. With the first reading failed, such a change now reads `hold not verified` or `hold refused` ([#624]).
- The relocation search reads a base's files in the order it finds them, where it read the PowerShell files (`.ps1`) after all the others, and on Windows the `--env-scan-home` sweep visits a directory's entries in the order the directory lists them, as on Linux and macOS, where it visited the files first and then the subdirectories, the last listed first. Only the order of the `relocation hint:` log lines, of `relocation.hints` and of the hint files' manifest rows changes ([#634]).
- A launchd property list value is read with `plutil -type` and then `plutil -extract KEY raw`, which prints the string as written, so a value holding `&` or `<` is now reported where it was refused; the `holds an XML entity` reason is gone. The `holds a newline` and `not a string` reasons stay ([#639]).
- On Linux and macOS a relative `-p` path that is not a directory is now joined to the current directory with `.` and `..` taken away by name, as an existing one already was and as on Windows, where it kept its spelling as typed minus one leading `./`: `-p ./gone/../x` is now logged and recorded as `<cwd>/x`, and `-p gone` and `-p ./gone/` are one project ([#635]).
- `collect` no longer tests whether it may enter or write the output directory before it starts: creating the staging directory there is the test. An output directory the run may not enter or write still ends the run with exit `2`, nothing left behind (but a staging directory `-k` keeps), but the message is now `Cannot create staging dir: mkdir DIR/.stage-NAME: REASON` (on Windows `mkdir DIR\.stage-NAME: Access is denied.`), or, on Windows under an account whose restore privilege is enabled, which lets a directory be made where no file can, `Cannot create manifest: open DIR\NAME.manifest.jsonl: Access is denied.` after the staging directory is made and, without `-k`, removed again, where it was `cd: can't cd to DIR` or `Output dir not writable: DIR`; a current directory that cannot be read for a relative `-o` now gives `Cannot read the current directory to resolve output dir DIR: REASON`. On Windows a directory in which files can be created but not deleted is no longer refused at the start, so the run's own steps report what it cannot do there ([#636]).
- On Windows the host name in the output file names, the first log line and `collection.json` `hostname` is the system's DNS host name, as on Linux and macOS, where it was the `COMPUTERNAME` variable: a NetBIOS name in capitals and cut to 15 characters. A host with a short name in capitals keeps its name; a longer name is now given whole, in the case it was set in ([#637]).
- `doubleagent --help` lists the `help` command, which prints the same text and was accepted but not listed ([#640]).
- In image mode (`-r`) the homes found no longer depend on the workstation: Windows now reads the image's `etc/passwd`, so a home outside the home parents (a service account's `/usr/share/ollama`) is collected there too, looks under `home` before `Users`, and keeps a home such as `home/shared` or `home/temp` that it dropped by name; a passwd home holding `\` is not read on Windows. The users and homes in `collection.json`, the manifest rows and the log lines follow that order, and a project that several users' agent state names is collected under the first of them in that order ([#633]).
- In image mode on Linux and macOS, a directory directly under the image's `Users` named `defaultuser0`, `UMFD-<n>`, `DWM-<n>` or `TEMP` (each also with a `.<suffix>`), or `Public`, `Default`, `Default User`, `All Users` or `Shared` in any letter case, is now dropped as a system or shared profile, and `-u` now ignores letter case, as on Windows. A live run on Windows finds homes as before; a live run on Linux or macOS changes only as the line for [#651] below says ([#633]).
- The log and the text the analysis commands print for a person now escape the invisible bidirectional controls (U+202A to U+202E, U+2066 to U+2069, U+200E, U+200F and U+061C) as `\u` and four hexadecimal digits, so a file name or evidence text holding a right-to-left override no longer shows in another order than it holds; the analysis commands now also escape U+2028 and U+2029, as the log did. The manifest, `collection.json` and the analysis output files hold the text as before ([#540]).
- On Linux and macOS a `SIGINT` or `SIGHUP` that was ignored when `doubleagent` started now stays ignored, in `collect` and in the analysis commands, so a run started in the background by a shell that is not interactive (`nohup doubleagent collect ... &` sent as a script) is no longer stopped by an interrupt; a `TERM` still stops it. The analysis commands now catch `SIGPIPE`: when the reader of their standard output goes away (`doubleagent detect ARCHIVE | head`) they print `error: the output could not be written: ...`, exit `2` and remove the archive they extracted, where the signal ended them (shell status `141`) and left the extracted directory behind ([#539]).
- A `collect` run whose standard error or standard output stays open but is no longer read (an EDR remote shell or a wrapper script that stopped reading) now finishes and writes its archive, where it blocked on the first write after the pipe filled and never ended. What the run prints is written by a writer of its own: up to 4,096 lines wait for the reader and further ones are not shown there; at the end the run waits up to five seconds, and the log file then ends with a new last line, `console: N lines not shown`, when some were not shown. N counts the progress lines, which the log file holds, and the lines of the stdout summary, which it does not; the summary's figures are in the `done:` line and `collection.json`. The output of `--inventory` is written directly, as before, once the progress lines before it have been taken or five seconds have passed, so with both streams sent to one file the progress lines come first ([#538]).
- `timeline` no longer writes and removes a `.write-probe-<random>` file in its output directory before parsing, so on Windows a directory where files can be created but not deleted is no longer refused. An output directory it cannot write to now fails at the first output file with the system's error (`error: DIR/timeline.jsonl: permission denied`, exit `2`), where it was refused before the parse with `the output directory DIR cannot be written to` ([#673]).
- In image mode (`-r`) on Linux and macOS, `collect` now takes the drive-letter project references of a Windows image (`C:\Users\alice\proj`, `file:///C:/x`, a JSON key or string such as `"C:\\proj"`), under the root, each part spelled as the disk holds it, unless two entries differing only in case match it, neither exactly. A live run on Linux or macOS reads every reference as before ([#675]).
- On Windows a registry relocation hint now resolves a reference to `ProgramData`, `ALLUSERSPROFILE` or `PUBLIC` (from the `ProfileList` key) and, in a user's keys, to the program folders such as `ProgramFiles` and `CommonProgramFiles(x86)` (from the `CurrentVersion` key), as a new logon sets them, where it was `references %NAME%`; a user's reference to `COMPUTERNAME` is no longer given the system key's value. `SystemDrive` is now always the drive of `SystemRoot` for the profile path and those names. The registry pass also reads each loaded hive's `Volatile Environment` key and its session subkeys, after the user's `Environment` key, so a relocation variable set there gives a hint whose `source` is `HKU\<SID>\Volatile Environment\NAME` or `HKU\<SID>\Volatile Environment\<session>\NAME`; such a key that cannot be read is logged `registry: KEY not readable: <message>` ([#645]).
- Kilo Code's pre-fork VS Code tasks (`tasks/<id>/` in the `kilocode.kilo-code` extension storage) are read as Roo Code's are, and their rows change form. The `task:` row now comes from the task's `history_item.json`, or else its `tasks/_index.json` entry, at that entry's line, in Roo Code's form `task: <task> | <key>=<value> ...` with the token counts, cost, mode, status and parent and root task ids it holds, followed by a `permission mode: <mode>` row when a mode is set; it came from `api_conversation_history.json` at line 0 as `task: <task> mode=<mode> status=<status>`. Each text block of a message is now its own row, of the message's role, except a user message's `<environment_details>` block, which stays a `system` row; a block of a type the reader does not know is a `[<type>]` row, where it was `<type>: <block JSON>`. The rows take the history item's `modelId` as their model, and `history_item.json` is now read ([#709]).

### Fixed

- Two members of a zip whose names are different with slashes alone but name one file once a backslash separates folders (`p/a\b.jsonl` and `p/a/b.jsonl`, or `p/a\.\b.jsonl` and `p/a/b.jsonl`) were extracted as one file: the later replaced the earlier with no problem line, and both manifest rows read the surviving file, so one transcript's rows were shown under the other file's name. The member whose name already is that path with slashes (`p/a/b.jsonl`) is now kept, wherever it comes in the zip, or, between two names that both need a backslash, the first; each other member is skipped with `<archive>: member <name> not extracted: its name and that of member <name> name one place when a backslash separates folders; <name> is kept`; a manifest row is given the file only when its `archive_path` names the kept member, and the other row is reported `missing from the collection`, and a file another file names by its path, such as a transcript's saved tool output, is read from the kept member. A member with the same name as an earlier one, empty and `.` parts aside, still replaces it ([#676]).
- On Windows, where a backslash separates folders in a tar member's name too, two members of a tar whose names name one file once a backslash separates folders were merged the same way: a collection from Linux or macOS holding both `a\b.jsonl` and `a/b.jsonl` gave both rows the later file's content. The member whose name already is that path with slashes is now kept as in a zip, the other skipped with the same problem line, and its row reported `missing from the collection` ([#678]).
- A zip member whose name reaches a file's place only because a backslash separates folders no longer takes that place when the two names also differ in letter case on a file system that folds case (`p/a\B.jsonl` against `p/a/b.jsonl` on macOS or Windows), or when one is a folder and the other a file (a folder `p/a\b.jsonl/` against the file `p/a/b.jsonl`): the member listed first was kept, and Info-ZIP lists the backslash name first. Members whose names hold no backslash are now extracted before those whose names hold one, so the member whose name is the path with slashes is kept and the problem line names the backslash member as not extracted; on Windows a tar holding a backslash name is read twice, the same way ([#680]).
- A zip member whose name holds a `.` part between backslashes (`p/a\.\b.jsonl`), and on Windows such a tar member, is now its manifest row's artifact; its row was reported both `missing from the collection` and `outside the collection`, because a row's `archive_path` kept the `.` part that extraction drops ([#679]).
- `collect` no longer waits for ever when the image's `etc/passwd` (or, on a live Linux or macOS run where `getent` does not run, the host's) is a named pipe or a link to one: the file is read only when it is a regular file, and the home parents are searched either way ([#648]).
- An unmatched Docker or Podman volume's `skipped_unmatched_volume` row now carries the times, `uid`, `gid` and `mode` of the volume's `_data` directory, read before anything lists it, as an excluded directory's row does, where they were `0` and `""` on every platform ([#630]).
- Writing the archive no longer looks up the owner and group name of each staged file on the host, which read the host's `/etc/passwd` and `/etc/group` on Linux and asked the directory service on macOS, only for the names to be left out of the archive. The archive does not change ([#629]).
- `collection.json` `users` and `homes` stay parallel: a home whose account has no name (a passwd line with an empty user name) has `""` in `users`, where the empty name was left out and every later user was paired with the home before its own ([#628]).
- Whether a TOML file was read as TOML 1.0 or TOML 1.1 depended on the `BURNTSUSHI_TOML_110` environment variable of the analyst's shell, so one collection could give two timelines; the variable no longer has any effect ([#569]).
- A TOML file that defines one key twice as an array is refused with an error row; the last array was kept silently ([#569]).
- A TOML file with an array of inline tables, one of them holding the empty key `""`, could give its settings rows one merged table with a `<nil>` value, or drop tables of the array; every row now shows the values the file holds, and such an array's tables list their keys sorted ([#570]).
- An excluded path that is itself a symbolic link (on Windows also a junction) now has a `skipped_excluded` row typed `symlink`, with the link's own metadata and size and its stored `target`, where it had a `dir` row when it led to a directory and a `file` row otherwise, both with an empty `target`; the link is never followed. The manifest interface changed: a `skipped_excluded` row can be typed `symlink` and carry a `target`. Based on [pull request 508](https://github.com/seanthegeek/doubleagent/pull/508) ([#507]).
- A file whose name ends in `|` was looked for under the name without it, so it was not collected, and another file by that shorter name could be collected twice; it is now collected under its own name ([#536]).
- With `-o` inside a directory the run collects, `collect` collected its own log, manifest and staging directory, and on Windows copied its own copies again, one level deeper each time, until the path grew too long. The run's own files and staging directory now get no row and are not archived, however `-o` names the directory ([#609]).
- On Linux and macOS, when catalog lines that differ only in letter case (`.config/goose` and `.config/Goose`) matched one directory on a case-insensitive file system, `collect` spelled the manifest `path` and the archive member as the line listed first spells it, so the spelling, and which `EXCLUDES` and `SECRET_GLOBS` lines applied, depended on the order of the catalog lines. The path now carries the spelling the directory holds, as on Windows, and the `EXCLUDES` and `SECRET_GLOBS` lines spelled as the disk is apply ([#584]).
- On Linux and macOS an `EXCLUDES` or `SECRET_GLOBS` line was matched byte for byte, so on a volume that ignores letter case (the default macOS volume, a `casefold` ext4 directory, a mounted FAT or APFS image) a directory spelled otherwise than the line escaped it: with `~/.config/Goose` on a Mac, `secrets.yaml` there and Cursor's `~/.config/Cursor/auth.json` were not flagged `secret: true` and were archived under `--no-secrets`, and an excluded directory such as `mcp-apps-cache` was collected. These lines now ignore ASCII case, so such files are flagged `secret: true` (`skipped_secret` under `--no-secrets`) and such directories get their `skipped_excluded` row. No manifest field changes ([#584]).
- When two catalog lines that differ only in letter case (`.config/Goose` and `.config/goose`) reach one directory on a file system that ignores letter case, the directory is collected once and recorded as it is spelled on disk, and on every platform the `collect --inventory` `evidence` field names the first of those patterns by agent and then pattern. The log no longer prints a line for the second catalog line; the manifest rows do not change ([#591]).
- A catalog line nested in another (`.gemini/antigravity` inside `.gemini`) and spelled otherwise than the disk (`.gemini/Antigravity`) had its files collected twice on a Linux or macOS file system that ignores case, once under each agent; they are now collected once, under the nested line's agent, spelled as on disk, or, below a directory that cannot be listed, as the first line spells it ([#585]).
- A Windows image mounted case-sensitively on Linux or macOS missed the catalog lines spelled in another case than the directory the install made (the Devin CLI's `AppData/Roaming/devin` lines, where the Devin IDE made `AppData/Roaming/Devin`), so their files were not collected or not flagged `secret: true`; they now match ([#587]).
- A symlinked directory that two catalog lines spell in different case (`.config/amp` and `.Config/goose` through a linked `~/.config`) got two `symlink` rows on a file system that ignores case; it now gets one, spelled as on disk, or, below a directory that cannot be listed, as the first line spells it ([#594]).
- On Windows the `size`, times and attributes of a manifest row are read from the file itself, through a handle on it, where they came from its directory entry, which NTFS updates later: a file an agent was still writing, or one written through another hard link, had an older size and write time, and a directory that had just gained a child an older write time. A file no handle can open, such as `pagefile.sys`, is still described by its directory entry ([#618]).
- A relocation value that ends in `|` and holds no other `|`, such as `CODEX_HOME=/opt/x|` in `/etc/environment`, an `environment.d` file or a launchd property list, is now reported as the file holds it, where the last `|` was dropped; `relocation.hints[].value` and the `relocation hint:` log line change for such a value ([#626]).
- On Windows a registry relocation hint now holds the value a new logon gives the variable: a `REG_EXPAND_SZ` value's `%NAME%` references are replaced once, from the system key, `SystemRoot`, `SystemDrive`, the user's `USERPROFILE`, `APPDATA` and `LOCALAPPDATA`, and the values Windows reads before it, where they were replaced in up to eight passes from every value of the key in any order. A reference to an expandable value listed later in the key, to a value an empty user value removes, or to `HOMEDRIVE` or `HOMEPATH` now leaves the value not resolved (`references %NAME%`), and the reason names the whole text between the first two `%`, so a name holding a space or starting with a digit is named where the reason was `holds a %`. A value that would pass 32,767 bytes is kept as written; once a key's replaced text would pass 1 MiB, which the log names, that value and the key's later expandable values are kept as written too; a value kept as written that still holds a reference is not resolved. A user `Path`, `LibPath` or `Os2LibPath` is not joined to the system value when the join would pass 32,767 bytes, and the variable keeps the system value ([#627]).
- On a live Linux or macOS run, a home that `getent`, `/etc/passwd` or `dscl` writes with a doubled or trailing slash (`/home/bob/`) was a second home beside the home parent's `/home/bob`, so the directory was walked twice and its files got two sets of manifest rows, and a shared profile so written (`/Users/Public/`) was collected as a home. Such a home is now taken without its empty segments, as in image mode: one home, spelled `/home/bob`, and `/Users/Public/` is skipped ([#651]).
- The home search read a passwd file (the image's `etc/passwd`, or the host's where `getent` does not run) whole into memory as one piece, so a huge or sparse file cost the run that much memory. It is now read a line at a time, so every account is still found in memory bounded by one line; a line longer than 64 KiB, which cannot be an account, is skipped and logged as `user homes: PATH: N lines longer than 64 KiB were skipped` ([#650]).
- `plutil` is now run only on macOS. On Windows and Linux, over a macOS image too, a launchd property list's variables get the reason `no plutil` and `capabilities.plutil` is `false`, whatever program of that name is on `PATH`; before, a `plutil` that was not Apple's was run and its failures read as no value ([#642]).
- A relocation value longer than 4,096 bytes, in a file or the registry, is no longer resolved: its hint names the source and the variable with the reason `longer than 4096 bytes` and no value, so a very long value no longer fills the log and `collection.json` with its text; the length is tested before any other reason of a value in every reader, so no reason quotes text from such a value ([#646]).
- Joining the lines of one `environment.d` assignment (a quote left open, or lines ending in a backslash) cost time that grew with the square of the number of lines, since the whole text so far was copied for each added line; it now costs time in proportion to the file. The `/etc/environment` reader joins nothing and is unchanged ([#653]).
- A `UserName` of any length in a launchd property list under `LaunchDaemons` became a relocation hint's `user`; a name longer than 255 bytes is now not taken as an account name, so the hint's user is empty, as for any other `UserName` that is not a plain account name ([#654]).
- In a directory whose listing fails part way, as on a damaged disk, a catalog line now matches the names read before the failure in any ASCII case and records the disk's spelling; it looked the name up only under the line's spelling, so on a disk that keeps case a line spelled `goose` missed a `Goose` the listing had returned, and on one that ignores case it recorded the line's spelling ([#613]).
- Finding the value of each relocation hint in `/etc/environment`, an `environment.d` file or a launchd property list looked through every assignment of the file, so a file of many assignments of one variable cost time that grew with the square of their number (3.3 s for 80,000 lines); each value is now found through an index built once, the last assignment of a line still winning, and the same file takes 0.5 s ([#656]).
- A relocation variable name split across two lines of `/etc/environment` by a backslash (`CODEX_\` then `HOME=/opt/elsewhere`), which pam_env joins into one assignment at login, gave no hint and the file was not collected; the lines are now also searched as pam_env joins them, and such a name is a hint on the join's first line with the reason `continued` ([#510]).
- Project discovery ran the project path in Gemini CLI's `.gemini/tmp/*/.project_root` and `.gemini/history/*/.project_root` files, which Gemini writes without a final line end, into the next path read, so those projects were lost or found as one wrong path; each line of such a file is now a path of its own, ending at a line feed, a carriage return and line feed, or the end of the file, where one final carriage return is dropped too ([#541]).
- On a live macOS run a home from the directory service (`dscl`) whose path holds a space (`/Users/Jane Doe`) was cut at the space, so it was not found for its account and `-u` with that account's name matched nothing; `collect` now reads `dscl -plist . -readall /Users NFSHomeDirectory RecordName`, whose property list keeps each value whole, and a record with two homes gives both, under the record's first name ([#541]).
- On Windows a registry relocation value whose name the key lists more than once is no longer reported with a value Windows may not use. Such a key holds a value whose name contains a NUL, written with the native registry call, which the listing cuts at the NUL; the program read the plainly named value's data for both listings. The hint now names the key and the variable once, with the reason `listed more than once` and no value. A value referring to such a name, or to one whose value cannot be read (`unreadable`), in the same key or in a user key read after the system key, is now left unresolved (`references %NAME%`), where before it was built from the value the name had before the key was read ([#659]).
- A file collected on Linux or macOS whose name holds a backslash (`a\b.jsonl`) was reported `missing from the collection` and never parsed when the collection was read on Linux or macOS as a tar or an extracted directory; a zip was not affected. Such a file now gives its rows from each, since a backslash separates folders in a row's paths only when the row comes from a Windows host (its `home` or `path` a drive or UNC path), and in its `archive_path` also when the collection came from a zip, whose member names are split the same way ([#664]).
- A file extracted from a zip archive now gets the modification time its member records, as a tar member does, instead of the time of the run, so in a zip without a manifest a row dated by `file mtime` carries that time ([#666]).
- Tar and zip member names follow one rule: leading slashes are dropped, and a name holding a `..` part or starting with a drive letter is skipped with `<archive>: member <name> not extracted: its name leads out of the extraction directory`. A tar member such as `.../p/a/../evil.jsonl` was extracted as `.../p/evil.jsonl`, possibly in place of the real file, and a zip member starting with a slash, which was skipped, is now extracted ([#667]).
- On Windows the analysis commands now extract an archive member named as a device (`CON.jsonl`) or ending in a dot or a space, as Linux and macOS did, where they skipped it with `its name holds a part this system cannot use as a file name`. A name NTFS refuses, such as one holding `?`, is still skipped with that line ([#671]).
- A manifest `collected` file row whose `size` is not a JSON integer (`true`, `1.5`, `"12"`) is now counted in `<n> manifest rows did not parse`, where it was read as 1, cut to an integer or parsed from the text. Every collector writes an integer, so no collection's output changes ([#674]).
- `detect`, `timeline` and `fleet` match the catalog against a loose tree (a directory with no manifest) by the rules `collect` uses: ASCII letter case is ignored and a `*` or `?` never matches a name's leading dot, so a Windows home's `AppData/Roaming/Devin` copied to a case-sensitive disk is attributed as in a collection and `.local/share/.x` no longer matches a `*`. Whether a project path is an agent's scratch directory (`inventory.json` `scratch_directories`) now ignores ASCII case in a Linux or macOS path too, and no longer takes a non-ASCII letter such as the Kelvin sign (U+212A) for `k` in a Windows path ([#665]).
- Project discovery in `collect` now decodes every percent escape of a `file://` folder URL (`%23` for `#`) on every platform, where Linux and macOS decoded only `%20`, so a VS Code-family, Antigravity, Kiro, Goose, Twinny or Tabby project whose path holds another escaped character is found and collected. A malformed escape (`%zz`) or a URL whose decoded path would hold a newline stays as written, and a path that is not a `file://` URL is no longer decoded (`/srv/a%20b` names a directory spelled with `%20`) ([#668]).
- A NUL byte in a file that project discovery in `collect` reads, such as the NULs a crash can leave at the end of a JSONL history, no longer discards the file: every line is read, and the projects it names are collected ([#669]).
- The project `collect` takes from a Twinny embeddings manifest (the deepest directory its files share) now compares path parts as bytes, so `/w/01/a.ts` and `/w/1/b.ts` give the project `/w`, where they gave `/w/01` ([#670]).
- On Windows `timeline` and `fleet` with a directory input no longer refuse an output path that runs through a junction or a symbolic link (`cannot tell whether the output ... is outside the input`): the link is followed to its directory, and the output is refused only when it then lies inside the input ([#672]).
- A live run on Windows now takes a project named by a `file:///c%3A/...` URL, as Antigravity writes its project folder, and by any drive URL in the Kiro, Goose and Twinny files read the same way; it dropped them. In image mode on Linux and macOS these URLs are now spelled as the disk holds them ([#683]).
- Project discovery in `collect` now reads a `\uXXXX` escape in a path from a JSON file as the character it names, so a project such as `/home/alice/café` that an agent writes as `"/home/alice/caf\u00e9"`, as Hermes writes every character outside ASCII in its checkpoint project files, is found and collected; it was looked up under the escaped text and missed. A lone half of a surrogate pair and an escape naming a backslash stay as written, and so does a whole value whose escape would put a newline or a NUL in the path ([#685]).
- On Windows the registry relocation pass takes `SystemRoot`, and the `SystemDrive` derived from it, from the running system's Windows directory, not from the `SystemRoot` value of the Windows version key, which Windows ignores when it builds a logon's environment; a hint whose value refers to `%SystemRoot%` or `%SystemDrive%` no longer follows an edit of the registry value ([#692]).
- A transcript or side file that the analysis commands were given but could not look at, such as a file in a directory that can be listed but not entered, now gives its `parser: <file> could not be read (<reason>)` row, where the parser gave no row for it and said nothing. An absent file, a link and an entry that is not a regular file still give none ([#698]).
- A SQLite database whose main file starts with a damaged header, while the rollback journal (`-journal`) or write-ahead log (`-wal`) beside it holds a good first page, is now read as SQLite reads it, where every parser of a database reported `parser: not a SQLite database`: the header is judged on the first page as SQLite sees it, after the journal is played back and the log applied. A database whose first page has a bad header only in the log is now reported `not a SQLite database` by every parser, where the Cline, OpenClaw and OpenCode parsers called it unreadable. A file that is not a database once a journal and a log that can be applied have been is reported as before; beside such a file, a `-wal` or `-journal` that cannot be read is now reported as that file `could not be read`, and a log or journal that cannot be applied (a log format SQLite does not support, a journal that leaves the file shorter than its header says) is now `parser: SQLite error: <message>` ([#694]).
- In an Antigravity conversation database, a step's protobuf field written with another wire type than its kind (a text field as a number) is now passed over, as a protobuf reader passes it over, where it was read as its kind and could give a row, such as a prompt reading `42`, the agent never held ([#695]).
- In an Antigravity conversation database, a step holding one protobuf message field twice now gives the members of both copies, merged as the protobuf encoding says (a later plain member replaces an earlier one, nested messages merge in turn, repeated members join), where the second copy replaced the first and a prompt in the first was lost ([#696]).
- In an Antigravity conversation database, a step holding a protobuf group (the deprecated wire types 3 and 4) is now read with the group passed over to its end tag, where the whole step was lost with `parser: 1 step(s) could not be decoded`; a group with no end, or an end with no group, still makes the step unreadable ([#697]).
- `doubleagent timeline` and the other analysis commands wrote no row for an agent directory spelled in another letter case (`.Claude` for `.claude`), which `collect` gathers and attributes. Every parser now picks its files ignoring the case of ASCII letters, as the catalog does, and a session id, project name or `source_file` keeps the spelling the disk gave. [Case variants in `docs/coverage.md`](docs/coverage.md#case-variants) says which joins of a file name with a name inside the evidence ignore case and which still compare it as written. ([#686])
- `doubleagent timeline` named the session of an Aider input history or LLM history row after the chat history spelled as Aider's own name for it (`.aider.chat.history.md`), whatever the disk spelled it, so one session had two session ids when the chat history is spelled in another letter case, such as `.Aider.Chat.History.md`; both now name the chat history as the disk spells it, as the chat history's own rows do ([#702])
- A file a parser looks for beside the one it reads (an index, a directory named by a session id, a SQLite `-wal` or `-journal` file) is now found when the disk spells it in another letter case, and the collection is read on a disk that keeps case (Linux); it was skipped, so its rows were missing ([#700])
- `doubleagent timeline` now joins a file or directory name to the id the evidence holds for it when the disk spells it in another ASCII letter case: a Cursor agent transcript to its composer in the editor's `state.vscdb`, a Cline, Roo Code, PearAI or Kilo Code task directory to its index entry, and a Continue or PearAI session file with no `sessionId` to its `sessions.json` entry. The rows take the entry's project, times and model, and its spelling of the id as `session_id`, where they lost them and carried a second session id (a Cursor transcript's rows were then kept as recovered copies); `source_file` keeps the disk's spelling. A name that two ids match, each only when letter case is ignored, takes neither ([#703]).
- A VS Code or Antigravity project on a network share, named by a `file://server/share/...` URI, now has the project path `\\server\share\...`, as Cursor already gave it, so one share is one project whichever of these agents names it; it was `//server/share/...`. This covers a VS Code `workspace.json` folder and a file URI in a VS Code or Antigravity message ([#707]).
- The `parser:` rows of Kilo Code's configuration, sandbox, retention and session-share files, Roo Code's state files and retry queues, PearAI's and Continue's session files, Twinny's conversations and Tabby's event files now leave `timestamp_utc` empty where they carried the file's modification time or the session's or event's time ([#708]).
- A Cline, Roo Code, PearAI or Kilo Code task file that holds `true` or `false` where a time belongs (`ts`) no longer empties the times of the task's records that have none of their own. In choosing the model of the task's rows, a `model_usage` entry whose `ts` is a string of digits now counts as time 0, where the task's `model:` rows already placed it, so the `model` column of the task's rows can change. The entry's own `model:` row keeps the time its string gives ([#710]).
- A Roo Code, Twinny or Tabby extension value in a `state.vscdb` that is not JSON now gives the JSON reader's reason, `parser: ItemTable value for <key> is not valid JSON (<reason>)`, as VS Code's and Cody's rows do, where it gave no reason. With `--no-secrets` the reason's detail after its line and column is replaced in the rows of Roo Code, Twinny, Tabby, VS Code, Cody and PearAI, since it quotes a character or an escape of the value; VS Code, Cody and PearAI showed it ([#711]).
- The `<environment_details>` block that Cline and Roo Code add to the end of each user message they send to the model, with the editor's open files, terminals and working directory, is now a `system` row, as PearAI's already was, where it was a `user` row counted among the session's `user_turns`. This holds for a task read from its `api_conversation_history.json` (when its `ui_messages.json` is gone) and for such a block in a Cline SDK session's messages file; a block that only mentions the tag later in its text stays a `user` row ([#712]).
- Tabby's `parser:` rows for a `config.toml` that is not valid TOML and for a `user_events` record whose `payload` is not a JSON object now leave `timestamp_utc` empty, as its other problem rows do, where they carried the file's modification time and the record's `created_at`. ([#714])
- A Cody chat saved by the VS Code extension from 1.0.0 to 1.8.0, which keeps a message's context files in the interaction's `usedContextFiles`, now names them on the user row's `[context: ...]` line, each by its `uri` or else its `fileName`, where the row named no file. ([#715])

### Removed

- The `collection.json` `capabilities` fields `hash_tool`, `archiver` and `grep_text`, which always held `crypto/sha256`, `archive/tar` and `true`, and the `hash=crypto/sha256` word of the log's second start line are removed; `capabilities` keeps `plutil`. This changes the `collection.json` interface ([#638]).
